# Отчёт по экспорту и сбору метрик DormitoryHelper

## Цель работы

Развернуть в Minikube VictoriaMetrics и организовать автоматический сбор
метрик приложения DormitoryHelper и PostgreSQL через pull-модель и Kubernetes
service discovery.

## Стек мониторинга

- VictoriaMetrics Single — хранение и выполнение MetricsQL/PromQL-запросов
- vmagent — обнаружение целей в Kubernetes, периодический scrape и remote write
- `prometheus-fastapi-instrumentator` — типовые HTTP-метрики FastAPI
- `prometheus-client` — собственные бизнес-метрики
- `postgres_exporter` — преобразование статистики PostgreSQL в формат Prometheus/OpenMetrics

## Метрики приложения

Backend предоставляет endpoint `/metrics` без авторизации. Библиотека
`prometheus-fastapi-instrumentator` экспортирует количество и длительность
HTTP-запросов, а `prometheus-client` — метрики процесса Python и бизнес-метрики.

Реализованы следующие бизнес-метрики типа `Counter`:

| Метрика | Метки | Назначение |
|---|---|---|
| `dormitory_helper_user_registrations_total` | — | Число успешных регистраций |
| `dormitory_helper_user_logins_total` | `outcome` | Число успешных и неуспешных попыток входа |
| `dormitory_helper_announcements_created_total` | `category` | Число созданных объявлений по категориям |
| `dormitory_helper_announcements_updated_total` | `category` | Число обновлённых объявлений по категориям |
| `dormitory_helper_announcements_deleted_total` | `category` | Число удалённых объявлений по категориям |

## Экспорт метрик PostgreSQL

В Pod PostgreSQL добавлен sidecar-контейнер
`quay.io/prometheuscommunity/postgres-exporter:v0.20.1`. Контейнер подключается к
PostgreSQL по `localhost:5432`, потому что контейнеры одного Pod разделяют
сетевое пространство имён. Экспортер публикует `/metrics` на порту `9187`.
Учётные данные берутся из существующих ConfigMap и Secret.

## Service discovery

Аннотации добавлены в шаблоны Pod двух Deployment:

```yaml
prometheus.io/scrape: "true"
prometheus.io/port: "8000" # 9187 для postgres_exporter
prometheus.io/path: "/metrics"
```

vmagent использует Kubernetes API с ролью обнаружения `pod`, оставляет Pod с
`prometheus.io/scrape=true`, выбирает указанный порт и выполняет scrape заданного
пути. Статического списка IP-адресов нет: после пересоздания Pod новая цель
обнаруживается автоматически.

## Установка VictoriaMetrics

Добавление Helm-репозитория:

```bash
helm repo add vm https://victoriametrics.github.io/helm-charts/
helm repo update
```

VictoriaMetrics Single:

```bash
helm upgrade --install vectoriametrics vm/victoria-metrics-single \
  --values k8s/monitoring/victoria-metrics-single-values.yml
```

vmagent с Kubernetes service discovery:

```bash
helm upgrade --install vmagent vm/victoria-metrics-agent \
  --values k8s/monitoring/vmagent-values.yml
```

## Проверка

```bash
kubectl get pods
kubectl get svc

kubectl port-forward \
  svc/vectoriametrics-victoria-metrics-single-server 8428:8428
```

Метрики проверяются в VMUI по адресу `http://localhost:8428/vmui/` запросами
`up`, `pg_up` и `dormitory_helper_announcements_created_total`.

Проверка vmagent:

```bash
kubectl port-forward \
  svc/vmagent-victoria-metrics-agent 8429:8429
```

На странице `http://localhost:8429/targets` у обеих прикладных целей состояние
должно быть `up`: backend на порту `8000` и postgres-exporter на порту `9187`.
